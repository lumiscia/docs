# Lumiscia Docs

Documentation site for Lumiscia, the hosted GPU rendering API, and Lumen, its open-source rendering engine developed in `lumiscia/lumen-oss`. Built with Fumadocs and TanStack Start, prerendered to static HTML and deployed to `docs.lumiscia.com` with Wrangler.

## General guidelines

- Do not edit AGENTS.md or CLAUDE.md unless explicitly asked.
- You may suggest glossary additions.

## Tooling

- Always use `vp` (Vite+). Never run pnpm, npm or yarn directly.
- Use `vp dlx` instead of `npx`/`dlx`. Do not install Oxlint or Oxfmt directly.
- Import config helpers from `vite-plus`, never from `vite`.
- `vp dev`, `vp build` etc. always run the built-in tool. To run a `package.json` script of the same name, use `vp run <script>`.
- Run binaries from dependencies with `vp exec`, for example `vp exec wrangler deploy`.
- Run `vp install` after pulling changes.
- Validate with `vp check` (format, lint and types) and `vp build` (prerenders every page).
- `just` is the task runner (`just --list`): `ready`, `dev`, `check`, `build`, `typegen`, `deploy-dry-run`.
- Do not hand-edit `src/routeTree.gen.ts` or `.source`; they are generated by the build.

## Code style

- Keep it simple and avoid speculative abstractions (YAGNI).
- Lean on type inference; annotate only where it adds clarity or is required.
- Write a few meaningful tests rather than many shallow ones.
- Avoid 1000+ line monoliths; split by responsibility.

## Content notes

- Pages live under `content/docs` as MDX.
- Update the nearest `meta.json` when adding, renaming or reordering pages.
- The prerender list is built from `content/docs` automatically, so new pages need no route or config changes.

## Git

- Use Conventional Commits, for example:
  - `docs: add webhooks guide`
  - `fix(nodes): correct blur radius range`
  - `chore: update dependencies`
- Do not revert unrelated changes.
- CI, not pre-commit hooks, is the source of truth.

## Glossary

- **Lumiscia**: the hosted rendering API and platform at `api.lumiscia.com`, with workspaces, API keys, media storage and GPU render workers.
- **Lumen**: the open-source rendering engine, developed in the `lumen-oss` repository and published as `@lumiscia/lumen-*` packages on npm and `lumen-server` on crates.io.
- **`@lumiscia/lumen-sdk`**: the TypeScript SDK for the API. Its client class is `Lumen`, with Node and Cloudflare entry points.
- **Composition**: the JSON document describing a video: timeline, render settings, nodes and the connections between them. It is the input to a render.
- **Render / render job**: a request to render a composition, submitted to the API and processed by a GPU render worker.
- **Node**: a single operation in a composition graph, such as a source, processing, compositing, vector or output node.
- **Manifest alias**: a key in a render request's top-level `media` manifest. The manifest maps each alias to a Lumen media id (`lumen:<media_id>`), and composition nodes reference media by alias.
- **Workspace**: the account that owns renders, API keys, media and balance.
- **Artifact**: the rendered output file produced by a render.
