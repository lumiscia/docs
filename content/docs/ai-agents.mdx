Every docs page is also published as Markdown, so an agent reads the same content you do without parsing HTML.

## Docs as Markdown

- [`llms.txt`](https://docs.lumiscia.com/llms.txt) lists every page with a one-line description, in the [llms.txt](https://llmstxt.org) format.
- [`llms-full.txt`](https://docs.lumiscia.com/llms-full.txt) holds every page in one file.
- Add `.md` to a page's URL to fetch that page alone, for example `https://docs.lumiscia.com/guides/animation.md`. The quick start is at `https://docs.lumiscia.com/index.md`.

Each page has a **copy page** button, and its menu opens the page in Claude or ChatGPT.

## Schemas

- The [OpenAPI spec](https://api.lumiscia.com/v1/openapi.json) describes the Lumiscia REST API.
- The [composition JSON schema](https://lumiscia.com/schema/composition.json) describes every field and node in a Lumen 0.6 composition, the version Lumiscia renders.

## Check compositions

Have the agent check each composition before it submits a render, so it fixes its own mistakes from the diagnostics. [`lumen check`](open-source/cli#check-a-composition) from the Lumen CLI checks a file locally, and `POST https://api.lumiscia.com/v1/renders/check` also applies Lumiscia's limits and checks your workspace's media (see [Check before you render](how-it-works#check-before-you-render)). Both report diagnostics with a stable `code` and a JSON pointer `path`.

Give the agent a test API key while it builds the integration. Test renders are free and finish with a sample video, so a mistake in its code costs nothing.
