---
title: Composition format
description: The JSON document a render takes, with its timeline, render settings, nodes and connections.
---

A composition is a JSON document that describes a video as a graph of nodes. You send it as `composition` in a render request, and the browser preview plays the same document. The canonical schema is `definitions/composition.schema.json` in the [lumen-oss repository](https://github.com/lumiscia/lumen-oss), generated from the Lumen engine source. `@lumiscia/lumen-types` publishes it as the `LumenComposition` type.

```json
{
  "timeline": { "fps": 30, "duration_frames": 90 },
  "render_settings": { "width": 1280, "height": 720 },
  "nodes": [
    { "id": 1, "type": "background", "params": { "paint": [18, 24, 32, 255] } },
    { "id": 2, "type": "media_output" }
  ],
  "connections": [{ "from_node": 1, "to_node": 2, "to_port": "source" }]
}
```

This renders 3 seconds of a dark [`background`](nodes/source/background) at 1280×720.

## Top-level fields

| Field             | Required | Description                                                          |
| ----------------- | -------- | -------------------------------------------------------------------- |
| `timeline`        | Yes      | Frame rate and length.                                               |
| `render_settings` | Yes      | Output size.                                                         |
| `nodes`           | Yes      | The nodes in the graph.                                              |
| `connections`     | Yes      | Edges from node outputs to node inputs.                              |
| `compositions`    | No       | Named templates that `clip` nodes play. See [Templates](#templates). |
| `functions`       | No       | Expression functions. See [Expressions](expressions#functions).      |
| `audio`           | No       | Audio tracks and clips. See [Audio](#audio).                         |
| `metadata`        | No       | An object for your own data. `name`, if set, must be a string.       |

Other top-level fields are ignored, so an editor can store its own state in the document. Everything else is strict. An unknown key in `timeline`, `render_settings`, a template, a node or a connection fails validation, as does an unknown node type or param. Lumen's errors name the JSON path at fault, such as `timeline.fps`.

## Timeline

`duration_frames` is the exact number of frames to render. `fps` is the frame rate and defaults to 30.

```json
{ "timeline": { "fps": 24, "duration_frames": 96 } }
```

## Render settings

`width` and `height` set the output size in pixels. They are the only keys, and `background_color` is an error. To fill the frame with a color or gradient, use a [`background`](nodes/source/background) node.

```json
{ "render_settings": { "width": 1920, "height": 1080 } }
```

## Nodes

Each node has an integer `id` that is unique within its graph, a `type`, and optional `params`. A repeated id fails validation. Params you leave out take their defaults.

```json
{
  "id": 3,
  "type": "merge",
  "params": {
    "blend_mode": "screen",
    "opacity": "=progress(0, 30)"
  }
}
```

Param names are snake_case. Enum params take string names, such as `"blend_mode": "screen"`. A string that starts with `=` is an [expression](expressions), evaluated on every frame. To store a literal string that starts with `=`, write `==`: `"==total"` is the text `=total`.

A color is an array of 3 or 4 integers from 0 to 255 (`[255, 128, 0]`, `[255, 128, 0, 255]`) or a hex string (`"#ff8000"`, `"#ff800080"`).

The [node reference](nodes) lists every node type with its params, defaults and ports.

## Connections

A connection wires one node's output to another node's input port.

```json
{ "from_node": 1, "to_node": 3, "to_port": "base" }
```

`to_port` is required. Every node has one output, so `from_port` is optional and can only be `output`. Input port names depend on the node:

| Port                      | Nodes                                            |
| ------------------------- | ------------------------------------------------ |
| `source`                  | `media_output`, `clip` and every processing node |
| `base`, `overlay`, `mask` | `merge` (`mask` is optional)                     |
| `a`, `b`                  | `boolean`                                        |
| `layers`                  | `switch`, `raster_multimerge`                    |

`layers` and the `source` port of `wgsl_shader` accept several connections. Layers stack in the order their connections appear, first at the bottom. Every other input takes one connection, and a second connection to it is an error. Every port carries `raster_frame` data.

A graph must contain exactly one `media_output` node, connected to the stream you want to render.

## Media references

`media_in.source` holds a manifest alias, not a file, URL or media id.

```json
{ "id": 4, "type": "media_in", "params": { "kind": "image", "source": "hero" } }
```

The render request's top-level `media` manifest maps each alias to uploaded media:

```json
{ "media": { "hero": "lumen:media_3f9a1c2b7d4e5f60" } }
```

The API rejects compositions that put an `http://` or `https://` URL where an alias belongs. See [Media sources](guides/media-sources) for uploads and the manifest.

## Templates

`compositions` holds reusable templates by name. A [`clip`](nodes/compositing) node plays one over a window of the parent's timeline, with its own timing and prop values.

```json
{
  "timeline": { "fps": 30, "duration_frames": 150 },
  "render_settings": { "width": 1280, "height": 720 },
  "compositions": {
    "title_card": {
      "timeline": { "duration_frames": 60 },
      "props": {
        "title": { "type": "string", "default": "Untitled" }
      },
      "nodes": [
        { "id": 1, "type": "text", "params": { "content": "=prop('title')", "font_size": 72 } },
        { "id": 2, "type": "media_output" }
      ],
      "connections": [{ "from_node": 1, "to_node": 2, "to_port": "source" }]
    }
  },
  "nodes": [
    {
      "id": 1,
      "type": "clip",
      "params": { "composition": "title_card", "start": 15, "props": { "title": "Chapter one" } }
    },
    { "id": 2, "type": "media_output" }
  ],
  "connections": [{ "from_node": 1, "to_node": 2, "to_port": "source" }]
}
```

A template has its own `nodes` and `connections`, with node ids scoped to the template, and its own `media_output`. Without `render_settings` it takes the parent's size. Without `timeline` it takes the parent's timeline, and a `timeline` without `fps` takes the parent's frame rate. Templates can contain clips of other templates, but not in a cycle.

`props` declares the values a template reads with `prop('name')`. Each prop has a `type` (`string`, `number`, `color` or `vec2`) and an optional `default`. A prop without a default is empty, 0, transparent or `[0, 0]`.

The clip's params control playback:

| Param         | Default  | Description                                                                   |
| ------------- | -------- | ----------------------------------------------------------------------------- |
| `composition` | `""`     | Template to play. Empty plays the clip's `source` input instead.              |
| `start`       | `0`      | Parent frame the clip starts at.                                              |
| `duration`    | `-1`     | Parent frames to play. `-1` plays the template to its end.                    |
| `offset`      | `0`      | Template frames to skip at the start.                                         |
| `speed`       | `1`      | Playback rate, greater than 0.                                                |
| `end`         | `"hide"` | What shows after the window: `hide` (nothing), `hold` (last frame) or `loop`. |
| `props`       | `{}`     | Prop values by name. Expressions here run on the parent's clock.              |

A template draws at its own size from the top-left corner of the parent's canvas. Place it with a `transform` node.

## Audio

`audio` lists `tracks` and `clips`. Each clip belongs to a track and plays an audio file by manifest alias in `source_id`.

```json
{
  "audio": {
    "tracks": [{ "id": "music", "volume": 0.8 }],
    "clips": [
      {
        "id": "intro",
        "track_id": "music",
        "source_id": "song",
        "start_ms": 0,
        "duration_ms": 3000
      }
    ]
  }
}
```

Clips take their timing in whole milliseconds. `start_ms` and `duration_ms` are required, and `source_start_ms` skips into the source. Frame and second timings (`start_frame`, `duration_frames`, `source_start_seconds`) are errors. Tracks and clips take a `volume` of 0 or more, and tracks also take `muted` and `solo`.

Every clip's `track_id` must name a track in `tracks`, and track and clip ids must be unique.

## Render limits

The Lumiscia API checks each render request against these limits before it queues the render:

| Limit                  | Value                 |
| ---------------------- | --------------------- |
| Frame rate             | Up to 60 fps          |
| `duration_frames`      | 1 to 10,800           |
| Output size            | Up to 3840×2160       |
| Nodes in `nodes`       | 1 to 250              |
| Composition JSON       | Up to 1,000,000 bytes |
| Media manifest entries | Up to 50              |

Your plan can set lower limits on resolution and output length. See [Pricing](pricing).
