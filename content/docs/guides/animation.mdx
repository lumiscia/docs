You animate a composition by giving params [expressions](../expressions) instead of fixed values. Lumen evaluates each expression on every frame, so a param can change over time.

```json
{
  "id": 4,
  "type": "transform",
  "params": {
    "translate_x": "=tween(-400, 0, 0, 0.6s, 'out_cubic')",
    "rotate": "=sin(time * 2) * 5"
  }
}
```

## Time

`frame` counts frames from 0, and `time` counts seconds. Durations such as `0.6s` or `300ms` convert to frames at the composition's frame rate, so the same expression keeps its timing at 24, 30 or 60 fps. Use `frame` when you want exact frame steps, such as cutting on frame 45.

## Fades and moves

`progress(start, end)` goes from 0 at frame `start` to 1 at frame `end` and holds at both ends. It suits fades:

```json
{ "id": 5, "type": "opacity", "params": { "opacity": "=progress(0, 1s)" } }
```

`tween(from, to, start, duration, ease)` moves between two values over `duration` frames from frame `start`. It works on numbers, vec2 and vec3 values, colors and path data.

```json
{
  "id": 2,
  "type": "text",
  "params": {
    "content": "Lumiscia",
    "position": "=tween(vec2(120, 340), vec2(120, 300), 10, 0.5s, 'out_expo')",
    "opacity": "=tween(0, 1, 10, 0.5s)"
  }
}
```

`ease` is an easing and defaults to `'linear'`. The `in_*` easings start slow, `out_*` end slow and `in_out_*` do both, in the `quad`, `cubic`, `quart`, `quint`, `sine`, `expo` and `circ` families. The `*_back` easings pull back or overshoot, `*_elastic` oscillate and `*_bounce` bounce. `cubic_bezier(vec2(x1, y1), vec2(x2, y2))` is a CSS-style curve you can pass anywhere an easing name goes. [Easings](../expressions#easings) lists them.

To animate a color, tween or `lerp` between two colors. This background shifts from slate to teal over 90 frames:

```json
{
  "id": 1,
  "type": "background",
  "params": { "paint": "=lerp(#1e293b, #0f766e, progress(0, 90))" }
}
```

## Keyframes

For more than two values, use a keyframe track. `keyframes(frame, keys...)` takes one `key(at, value, ease)` per key, and each key's `ease` shapes the curve toward the next key. This title slides in, rests, and leaves:

```json
{
  "id": 2,
  "type": "text",
  "params": {
    "content": "Lumiscia",
    "font_size": 96,
    "position": "=keyframes(frame, key(0, vec2(-400, 300), 'out_expo'), key(20, vec2(120, 300), 'hold'), key(70, vec2(120, 300), 'in_cubic'), key(90, vec2(1400, 300)))"
  }
}
```

Before the first key and after the last, the value holds. A `'hold'` key keeps its value until the next key and then jumps, which also steps text: `=keyframes(frame, 'hold', key(0, 'ten'), key(30, 'hundred'))`. Two path data strings with the same commands interpolate point by point, so `keyframes` and `lerp` can morph a [`path`](../nodes/vector/path)'s `data`.

## Springs

`spring(t)` rises from 0 to 1 with a physical spring, where `t` is the time in seconds since release. To release at frame 12:

```json
{
  "id": 6,
  "type": "transform",
  "params": {
    "scale_x": "=spring((frame - 12) / fps)",
    "scale_y": "=spring((frame - 12) / fps)"
  }
}
```

`spring(t, stiffness, damping)` takes a stiffness (default 170) and damping (default 26). Lower damping bounces more.

## Paths and noise

`path_point(path_data, t)` is the point `t` of the way along a path, by arc length, and `path_angle(path_data, t)` is the direction it heads there, in degrees. Together they move a layer along a curve at a steady speed and turn it to follow:

```json
{
  "id": 3,
  "type": "shape",
  "params": {
    "geometry_kind": "rectangle",
    "width": 60,
    "height": 30,
    "fill_paint": "#f5b301",
    "position": "=path_point('M 100 400 C 400 100 800 700 1180 400', progress(0, 3s))",
    "rotation": "=path_angle('M 100 400 C 400 100 800 700 1180 400', progress(0, 3s))"
  }
}
```

`noise(seed, x)` is a smooth curve from -1 to 1 that varies about once per unit of `x`, so `=noise(1, time * 2) * 6` wobbles a rotation by up to 6 degrees, twice a second. `random(seed, x)` is a fixed random number from 0 up to 1, such as one per glyph with `random(glyph)`. Both give the same result on every render.

## Per-glyph text

A `text` node evaluates `glyph_offset`, `glyph_scale`, `glyph_rotation` and `glyph_opacity` once per glyph. In those params, `glyph`, `word`, `line` and `span` give the index of the glyph being drawn, so you can stagger each one:

```json
{
  "id": 2,
  "type": "text",
  "params": {
    "content": "One glyph at a time",
    "font_size": 72,
    "glyph_opacity": "=tween(0, 1, 10 + glyph * 2, 12)",
    "glyph_offset": "=tween(vec2(0, 24), vec2(0, 0), 10 + glyph * 2, 12, 'out_cubic')"
  }
}
```

Each glyph starts 2 frames after the one before it. Use `word`, `line` or `span` in place of `glyph` to stagger words, lines or spans.

## Reusable motion

Put motion you repeat into a function in the top-level `functions` object, then call it from any param:

```json
{
  "functions": {
    "rise(start)": "tween(0, 1, start, 12, 'out_cubic')"
  }
}
```

`"opacity": "=rise(20)"` then fades in from frame 20. See [Functions](../expressions#functions).

## Clip timing

A `clip` node plays a template on its own clock, so the template's animation starts when the clip does. `start` sets the parent frame it begins on, `speed` changes its playback rate, `offset` skips into it, and `end` chooses whether it hides, holds its last frame or loops when it finishes.

```json
{
  "id": 7,
  "type": "clip",
  "params": { "composition": "title_card", "start": 30, "speed": 1.5, "end": "hold" }
}
```

See [Templates](../composition-format#templates) for defining the template.
