---
title: Webhooks
description: Get a POST from Lumiscia when a render succeeds or fails.
---

Set `webhookUrl` when you create a render, and Lumiscia sends a `POST` to that URL when the render succeeds or fails.

```ts
import { Lumen } from "@lumiscia/lumen-sdk";

const lumen = new Lumen({
  apiKey: process.env.LUMISCIA_API_KEY!,
  baseUrl: "https://api.lumiscia.com/v1",
});

const { id } = await lumen.render(composition, {
  webhookUrl: "https://example.com/webhooks/lumiscia",
});
```

Without the SDK, add `webhookUrl` next to `media` and `composition` in the body of `POST /v1/renders`. The URL must use `https` and can't point at `localhost` or contain credentials.

## Events

A render sends one webhook, for one of two events:

| Event              | Sent when                                  |
| ------------------ | ------------------------------------------ |
| `render.succeeded` | The artifact is ready to download.         |
| `render.failed`    | The render failed. Failures aren't billed. |

Webhooks don't report queue position or progress. For those, use `waitForRender()` with `onProgress` from the [Node SDK](../sdks/node#wait-for-a-render).

## Payload

The body is JSON:

```json
{
  "event": "render.succeeded",
  "status": "succeeded",
  "id": "r_3f9a1c2b7d4e",
  "organizationId": "org_01J8Z3K4M5N6P7Q8R9S0T1V2W3",
  "createdAt": "2026-10-30T12:00:04.512Z",
  "durationMs": 7350,
  "costMicros": 14700,
  "artifactUrl": "/v1/renders/r_3f9a1c2b7d4e/artifact",
  "outputBytes": 1843200,
  "resolution": "1280x720"
}
```

| Field            | Description                                                                       |
| ---------------- | --------------------------------------------------------------------------------- |
| `event`          | `render.succeeded` or `render.failed`.                                            |
| `status`         | `succeeded` or `failed`.                                                          |
| `id`             | The render id.                                                                    |
| `organizationId` | The workspace that owns the render.                                               |
| `createdAt`      | When the render reached this status, in ISO 8601.                                 |
| `durationMs`     | Billed render time in milliseconds, at least 5,000 for a render that succeeds.    |
| `costMicros`     | Charge in millionths of a dollar. `14700` is $0.0147.                             |
| `artifactUrl`    | Path of the artifact, relative to `https://api.lumiscia.com`. Present on success. |
| `outputBytes`    | Artifact size in bytes. Present on success.                                       |
| `resolution`     | Artifact size as `<width>x<height>`. Present on success.                          |
| `error`          | Why the render failed. Present on failure.                                        |

Download the artifact from `artifactUrl` with your API key, or call `download(id)`. Artifacts expire; the render's `outputExpiresAt` gives the time, and [Pricing](../pricing) lists retention per plan.

## Delivery

Webhooks are signed with the [Standard Webhooks](https://www.standardwebhooks.com) scheme. Each delivery carries these headers:

| Header              | Value                                                                                                                                                          |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `webhook-id`        | Id of the delivery. The same on every retry.                                                                                                                   |
| `webhook-timestamp` | Unix time in seconds when the attempt was sent.                                                                                                                |
| `webhook-signature` | `v1,` and a base64 HMAC-SHA256 of `<webhook id>.<timestamp>.<body>`, signed with your workspace's `whsec_` secret. Several signatures are separated by spaces. |
| `user-agent`        | `Lumen-Webhooks/1.0`                                                                                                                                           |

Return a `2xx` status to acknowledge a delivery. Lumiscia makes up to 3 attempts when your endpoint returns any other status, 2 seconds and then 4 seconds apart.

## Verify signatures

`verifyWebhook` from `@lumiscia/lumen-sdk` checks the signature and the timestamp, then returns the typed event. Pass it the raw body exactly as received, since parsing and re-serializing the JSON breaks the signature. This handler takes a web `Request`, as in Cloudflare Workers, and your workspace's webhook signing secret:

```ts
import { LumenWebhookError, verifyWebhook } from "@lumiscia/lumen-sdk";

export async function handleWebhook(request: Request, secret: string): Promise<Response> {
  let event;
  try {
    event = await verifyWebhook({
      body: await request.text(),
      headers: request.headers,
      secret,
    });
  } catch (error) {
    if (error instanceof LumenWebhookError) {
      return new Response(error.code, { status: 400 });
    }
    throw error;
  }

  if (event.event === "render.succeeded") {
    console.log("Render ready:", event.id, event.artifactUrl);
  } else {
    console.log("Render failed:", event.id, event.error);
  }
  return new Response(null, { status: 204 });
}
```

`headers` also takes a plain object, such as Node's `request.headers`, and `body` takes a string, `ArrayBuffer`, or `Uint8Array`. `toleranceSeconds` sets how far `webhook-timestamp` may be from the current time, 300 seconds by default.

If a delivery can't be trusted or parsed, `verifyWebhook` throws a `LumenWebhookError` with one of these codes:

| Code                     | Meaning                                                                       |
| ------------------------ | ----------------------------------------------------------------------------- |
| `missing_headers`        | A `webhook-*` header is missing, or `webhook-timestamp` isn't a Unix time.    |
| `invalid_secret`         | The secret isn't `whsec_` followed by base64.                                 |
| `timestamp_out_of_range` | `webhook-timestamp` is further from the current time than `toleranceSeconds`. |
| `invalid_signature`      | No `v1` signature matches the body.                                           |
| `invalid_payload`        | The body isn't JSON, or isn't a render event.                                 |

## Handling deliveries

- Use `webhook-id` or the render `id` to ignore duplicate deliveries.
- Verify the signature before making changes your users can see, such as publishing the video.
- Ignore payload fields you don't recognize. New fields can appear.
