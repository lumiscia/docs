title: How It Works
description: The public model for Lumen compositions, validation, media loading, and frame rendering.
---

Lumen renders a directed node graph frame by frame. The graph starts from source nodes, passes through processing and compositing nodes, and ends at one `media_output` node.

## Composition Model

A composition contains:

- `timeline`: frame rate and total frame count.
- `render_settings`: output width, height, and optional background color.
- `nodes`: graph nodes, each with an id, type, and properties.
- `connections`: edges between node output ports and input ports.

```json
{
  "timeline": { "fps": 30, "duration_frames": 120 },
  "render_settings": { "width": 1280, "height": 720 },
  "nodes": [],
  "connections": []
}
```

## Validation

Lumen validates a composition before rendering:

- The graph has exactly one `media_output`.
- Every required input is connected.
- Every connection references existing nodes and ports.
- Output port kinds match input port kinds.
- The graph does not contain cycles.
- Node properties are valid for their node type.

Validation errors are meant to be shown directly in builder UIs. They usually point to a specific node, port, or property.

## Port Kinds

Ports are typed:

- `raster_frame`: pixel data such as video, images, text, and rendered shapes.
- `vector`: reserved for future editable geometry flows.

Shape, path, and text nodes produce raster frames directly, so they can connect to processing, compositing, and output nodes without a separate renderer node.

## Frame Evaluation

Rendering is demand-driven. For a requested frame, Lumen walks upstream from `media_output` and evaluates only the nodes needed for that result.

This means:

- Unconnected graph branches do not render.
- Switches and time remaps can avoid evaluating unused branches.
- A node reused by multiple downstream nodes can be cached for the current frame.
- Expressions are evaluated per frame.

Common expression values include:

- `frame`: zero-based frame index.
- `time`: current time in seconds.
- `fps`: composition frame rate.
- `width` and `height`: output dimensions.
- `duration_frames`: total composition length.

```json
{
  "type": "transform",
  "properties": {
    "translate_x": "=sin(time * 3.14159) * 120",
    "translate_y": "=frame * 0.5",
    "scale_x": 1,
    "scale_y": 1,
    "rotate": "=time * 12"
  }
}
```

## Media Loading

`media_in` nodes reference uploaded images or videos by alias. In the current API flow, the render request includes a top-level `media` manifest that maps each alias to a validated upload id from `/api/v1/media`.

```json
{
  "id": 1,
  "type": "media_in",
  "properties": {
    "kind": 0,
    "source": "hero"
  }
}
```

```json
{
  "media": {
    "hero": "lumen:media_abc123"
  },
  "composition": {}
}
```

Video sources can use trim ranges, playback speed, and loop modes. Lumen can determine which source frame is needed before rendering a composition frame, which helps previews and render workers preload only the required media.

## Output

`media_output` is the final sink. It accepts one raster input and returns the composition frame.

## Practical Limits

Large compositions should keep graph depth, media resolution, canvas size, and total rendered frames reasonable. See [Pricing](pricing) for cost behavior and optimization guidance.
