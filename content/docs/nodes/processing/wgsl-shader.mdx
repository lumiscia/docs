`wgsl_shader` runs your own WGSL compute shader over the rasters connected to `source`. Use it for effects the built-in nodes don't cover, such as rearranging channels.

<NodeReference type="wgsl_shader" />

## Example

The engine appends a prelude that binds the first input as `input0`, later inputs as `input1`, `input2` and so on in connection order (16 inputs at most), the output texture as `output`, a linear sampler as `input_sampler`, and frame globals as `lumen` (`resolution`, `time` and `frame`). Declare your own uniform struct at `@group(0) @binding(1)`. The entry point is `cs_main`, and it must declare `@workgroup_size(8, 8, 1)`.

Every input holds linear light with premultiplied alpha, and the output is read the same way. Values above 1 are brighter than white and are kept. The output, and any storage texture you declare, must be `texture_storage_2d<rgba16float, write>`. The engine clamps the output's alpha to 0 to 1 and turns NaN into 0. Color uniforms arrive as linear light, premultiplied; numbers and vectors arrive as written. For a formula written for sRGB-encoded values, the prelude has `lumen_srgb_to_linear` and `lumen_linear_to_srgb`, which take and return `vec3<f32>`.

This shader inverts colors by `amount`:

```wgsl
struct Params { amount: f32 };
@group(0) @binding(1) var<uniform> params: Params;

@compute @workgroup_size(8, 8, 1)
fn cs_main(@builtin(global_invocation_id) id: vec3<u32>) {
  let size = textureDimensions(output);
  if (id.x >= size.x || id.y >= size.y) {
    return;
  }
  let color = textureLoad(input0, vec2<i32>(id.xy), 0);
  let inverted = vec3<f32>(color.a) - color.rgb;
  textureStore(output, vec2<i32>(id.xy), vec4<f32>(mix(color.rgb, inverted, params.amount), color.a));
}
```

Set `shader` to that source and `uniforms` to `{ "amount": "=progress(0, 30)" }` to fade the effect in over the first 30 frames.
