---
title: Platform support
description: Which operating systems, GPU backends, and encoders Lumen supports when you run it yourself.
---

Lumen needs a GPU for its main render paths. The supported native targets are Linux with Vulkan and macOS with Metal. This page follows the [support matrix](https://github.com/lumiscia/lumen-oss/blob/main/docs/support-matrix.md) in lumen-oss.

It applies to running Lumen yourself. Hosted renders run on Lumiscia's GPU workers, and browser previews depend on the browser's WebGPU or WebGL support.

| Area                       | Status                 | Notes                                                                                                |
| -------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------- |
| Linux / Vulkan             | Supported              | Primary native render path. CI runs on Ubuntu with software Vulkan (lavapipe).                       |
| macOS / Metal              | Supported              | Metal rendering and VideoToolbox encoding. Not covered by CI.                                        |
| Windows                    | Basic development only | TypeScript packages and pure Rust crates build. Native rendering, FFmpeg, and `lumen-server` do not. |
| NVIDIA / CUDA              | Experimental fast path | CUDA/NVENC interop on Linux for hardware video paths.                                                |
| AMD / Intel Vulkan         | Experimental           | Uses the Vulkan renderer without CUDA interop. Not covered by CI.                                    |
| Software Vulkan / lavapipe | CI-covered baseline    | Runs the SDK and server integration tests. Validates behavior, not performance.                      |
| CPU encoding               | Supported baseline     | CPU-backed FFmpeg encoding. The fallback when hardware encoding is unavailable.                      |
| Hardware encoding          | Experimental           | CUDA/NVENC on Linux, VideoToolbox on macOS. Depends on OS, driver, FFmpeg, and adapter.              |

## Linux

Linux with Vulkan is the main open development path. AMD, Intel, and NVIDIA hardware all use the same Vulkan renderer, but CI only runs software Vulkan, so hardware-specific behavior is untested there. On NVIDIA, CUDA/NVENC interop is the fastest path. Treat it as experimental until you have validated your driver, FFmpeg build, and adapter.

The Debian and Ubuntu packages CI installs are listed under [Self-hosting](self-hosting).

## macOS

macOS renders through Metal and encodes with VideoToolbox where available. CI does not run macOS jobs, so macOS support relies on local development and release validation.

## Windows

Windows CI builds the TypeScript packages (except the generated WASM bindings) and checks the pure Rust crates: `lumen-engine`, `lumen-engine-gpu`, `lumen-generators`, `lumen-engine-macros`, and `lumen-engine-text`.

Native rendering, FFmpeg-backed media, `lumen-server`, the WASM and type generation scripts, and hardware encoding are unsupported. See [Windows development](https://github.com/lumiscia/lumen-oss/blob/main/docs/windows.md) for setup.

## Encoding

CPU-backed FFmpeg encoding is the portable baseline. Hardware encoding is opportunistic. When no compatible hardware encoder interop path exists, CPU encoding is the expected fallback.

## CI coverage

CI does not cover macOS or Metal, native Windows rendering, physical NVIDIA, AMD, or Intel GPUs, or hardware encoder paths.
