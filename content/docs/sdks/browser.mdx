title: Browser
description: Build and preview compositions in the browser, and render them through your backend.

Browser code builds and previews compositions. Your backend uploads media and creates renders, because every Lumiscia API call needs your API key.

<Callout type="error" title="Never ship an API key to the browser">
  An API key can spend your workspace balance and read its renders and media. Keep it on your
  server. The media upload URL also requires the key, so the browser can't upload to Lumiscia
  directly. Send files to your backend and call `uploadMedia` there.
</Callout>

| Task                                    | Package                                                                                               | Runs in            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------ |
| Build composition JSON                  | `@lumiscia/lumen-shared`                                                                              | Browser            |
| Preview a composition                   | `@lumiscia/lumen-react` or `@lumiscia/lumen-svelte`, or `@lumiscia/lumen-preview` without a framework | Browser            |
| Check a composition                     | `@lumiscia/lumen-bindings`                                                                            | Browser or Node.js |
| Upload media, create and follow renders | `@lumiscia/lumen-sdk`                                                                                 | Server             |

## Build a composition

`@lumiscia/lumen-shared` only builds JSON. It makes no network calls and needs no key, so it is safe in client code. See the [Composition builder](../guides/composition-builder) guide for the full API.

```bash
npm install @lumiscia/lumen-shared
```

```ts
import { Composition, nodes as n } from "@lumiscia/lumen-shared";

const composition = new Composition({
  renderSettings: { width: 1280, height: 720 },
  timeline: { fps: 30, durationSeconds: 3 },
}).addOutput(
  n.merge({
    base: n.background({ paint: [18, 24, 32, 255] }),
    overlay: n.media_in({ kind: "image", source: "hero" }),
  }),
);
```

The `media_in` node reads the source `hero`. In preview, you pass a local file under that name. At render time, the backend uploads the file and points the source at the upload's `asset:<id>`.

## Preview

The [React](react) and [Svelte](svelte) packages play the composition in a worker, with the Lumen engine compiled to WebAssembly. Pass local files to the player's `media` prop, keyed by source name, for example `{ hero: file }`. A source can be a `File` or `Blob`, a URL string or `URL`, or raw bytes, so you can preview a file before it is uploaded.

The preview needs a browser with WebGPU and `OffscreenCanvas`. WebGPU also needs HTTPS or localhost.

### Without a framework

`@lumiscia/lumen-preview` is the preview the framework packages wrap. `mountPreview` puts a canvas in an element and plays the composition there.

```bash
npm install @lumiscia/lumen-preview @lumiscia/lumen-bindings @lumiscia/lumen-shared
```

```ts
import { createLumenPreview, mountPreview } from "@lumiscia/lumen-preview";
import { runtime } from "@lumiscia/lumen-bindings/urls";

const preview = createLumenPreview();
const session = mountPreview(document.querySelector("#player")!, {
  preview,
  composition,
  media: { hero: file },
  runtime,
  loop: true,
});

preview.subscribe(() => {
  const { isLoaded, frame, totalFrames } = preview.getSnapshot();
  console.log(isLoaded, frame, totalFrames);
});
```

`mountPreview` takes the same inputs and playback options as the React and Svelte `Player`, plus `runtime`, the manifest of the [runtime files](#runtime-files). `session.setInputs()` changes them while it plays. It replaces every input, so one you leave out returns to its default, and an input that is unchanged does nothing. It serializes the composition on every call to pick up edits made in place, so call it when an input may have changed, not on every frame. `session.dispose()` stops the preview and removes the canvas.

The object from `createLumenPreview()` is read-only: it has `subscribe`, `getSnapshot`, `play`, `pause`, `seek` and `whenReady`, and only the session mounted with it changes its state. `getSnapshot()` returns the same object until the state changes, then a new one, so it works with `useSyncExternalStore`.

`@lumiscia/lumen-preview` exports `createLumenPreview`, `mountPreview`, `LumenPreviewContext`, `LumenPreviewSession` and the types of their state, errors, options and callbacks, including `LumenRuntime`. Media decoding and audio are internal. Render failures are logged only after you set a log level with `setLogLevel`.

## Runtime files

The preview renders in a worker that loads a wasm module, and plays audio through a second worker and an audio worklet. All four files come from `@lumiscia/lumen-bindings`, which names them in a manifest: `runtime` from `@lumiscia/lumen-bindings/urls`, or `runtime2d` from `@lumiscia/lumen-bindings/urls-2d` for the [2D-only build](#2d-only-build). Each entry is `{ file, url }`: `url` is where the file is served by default, found next to the package with Vite or plain ESM, and `file` is its name in a directory you host yourself.

| Entry          | `file` in `runtime`  | `file` in `runtime2d`   |
| -------------- | -------------------- | ----------------------- |
| `worker`       | `worker.js`          | `worker-2d.js`          |
| `wasm`         | `lumen_wasm_bg.wasm` | `lumen_wasm_2d_bg.wasm` |
| `audioWorker`  | `audio-worker.js`    | `audio-worker.js`       |
| `audioWorklet` | `audio-worklet.js`   | `audio-worklet.js`      |

To host them yourself, from your own path or a CDN, copy the four files of one manifest from `@lumiscia/lumen-bindings` into one directory and pass its URL as `runtimeUrl`. The `/worker`, `/worker-2d`, `/wasm`, `/wasm-2d`, `/audio-worker` and `/audio-worklet` exports name each file for a copy step or a bundler's asset imports.

```tsx
<Player preview={preview} composition={composition} runtimeUrl="/lumen-runtime/" />
```

```ts
mountPreview(host, { preview, composition, runtime, runtimeUrl: "/lumen-runtime/" });
```

`runtimeUrl` names a directory whether or not it ends with `/`, and a query on it is kept on each file. To serve one file somewhere else, pass a manifest of your own, such as `{ ...runtime, wasm: { file: "lumen_wasm_bg.wasm", url: "https://cdn.example/lumen.wasm" } }`.

The files can be on another origin that sends CORS headers. A worker on another origin starts from a `blob:` URL that imports it, so a Content Security Policy must allow `blob:` and that origin in `worker-src`, and `script-src` needs `'wasm-unsafe-eval'`.

With Vite 6 or 7 and no `runtimeUrl`, keep `@lumiscia/lumen-bindings` out of the dev server's dependency pre-bundling, or the runtime files 404. Vite 8 and `vite build` need nothing.

```js title="vite.config.js"
export default defineConfig({
  optimizeDeps: { exclude: ["@lumiscia/lumen-bindings"] },
});
```

### 2D-only build

The default build renders 2D and 3D nodes, and reads glTF models with Draco, meshopt and WebP compression. KTX2 textures stay out of the browser build, though `lumen` and `lumen-server` read them. A page that only shows 2D compositions can load the 2D-only build instead, which has no 3D and is about a quarter smaller to download (1.23 MB against 1.65 MB, brotli-compressed). It reports each 3D node as a `node.unsupported` error.

Import `Player` and `createLumenPreview` from `@lumiscia/lumen-react/2d` or `@lumiscia/lumen-svelte/2d`. With `mountPreview`, pass `runtime: runtime2d`. A bundler emits only the build a page imports.

```ts
import { runtime2d } from "@lumiscia/lumen-bindings/urls-2d";

mountPreview(host, { preview, composition, runtime: runtime2d });
```

## Check a composition

`@lumiscia/lumen-bindings` loads the engine on the calling thread to inspect compositions without rendering them. Import it from the entry point that fits where the code runs:

| Entry point                                                         | Use                                                                |
| ------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `@lumiscia/lumen-bindings/urls`, `@lumiscia/lumen-bindings/urls-2d` | The [runtime manifests](#runtime-files), without loading any file. |
| `@lumiscia/lumen-bindings`                                          | Browsers, with or without a bundler.                               |
| `@lumiscia/lumen-bindings/node`                                     | Node.js.                                                           |

`check` returns the same diagnostics as [`lumen check`](../open-source/cli#lumen-check), each with a `severity`, a `code`, a JSON pointer `path`, the `node` it's about when there is one, and a `message`. Pass the font families the page provides, and it also warns of text in any other family, which renders in the default font:

```ts
import { loadLumenBindings } from "@lumiscia/lumen-bindings";

const { check } = await loadLumenBindings();

const diagnostics = check(JSON.stringify(composition), ["Inter"]);
const ok = diagnostics.every((diagnostic) => diagnostic.severity !== "error");
```

`check` doesn't fetch media, so a missing file isn't one of its errors. Handle codes you don't know by their `severity`, because new codes can appear in a patch release.

`mediaDependencies(json)` lists what a composition needs before it renders: `{ media, dynamic, fonts }`. Each `media` entry has the `source` as written, the `kinds` it is read as, and its `uses`. Sources that an expression computes are in `dynamic`, and the font families its text names are in `fonts`.

`modelInfo(bytes)` lists the animation clips, materials and cameras of a binary glTF (`.glb`), which a `model_3d` selects with `animation`, `texture_material` and `camera`:

```ts
const { modelInfo } = await loadLumenBindings();
const { animations, materials, cameras } = modelInfo(new Uint8Array(await file.arrayBuffer()));
```

`mediaDependencies` and `modelInfo` throw on input they can't read. An engine failure is an `Error` with the engine's diagnostic `code`, `media` when a file is the cause, and `diagnostics` when a composition doesn't parse. The result types, such as `Diagnostic`, `MediaInventory` and `ModelInfo`, are in `@lumiscia/lumen-types`.

## Render through your backend

Send the composition JSON and the file to your backend:

```ts title="client.ts"
const form = new FormData();
form.append("composition", JSON.stringify(composition.toJSON()));
form.append("hero", file);

const response = await fetch("/api/renders", { method: "POST", body: form });
const { id } = await response.json();
```

On the server, upload the file and create the render. This example uses Node.js. On [Cloudflare Workers](cloudflare), import from the same package and read the key from the Worker's environment.

```ts title="server.ts"
import { Lumen, assetSource } from "@lumiscia/lumen-sdk";

const lumen = new Lumen({
  apiKey: process.env.LUMISCIA_API_KEY!,
  baseUrl: "https://api.lumiscia.com/v1",
});

export async function createRender(form: FormData) {
  const composition = JSON.parse(String(form.get("composition")));
  const file = form.get("hero") as File;

  const hero = await lumen.uploadMedia({ body: file });
  for (const node of composition.nodes) {
    if (node.type === "media_in" && node.params?.source === "hero") {
      node.params.source = assetSource(hero);
    }
  }

  return lumen.render(composition);
}
```

Lumiscia renders take uploaded images, video, audio and fonts. A `.glb` model, an environment map or a LUT can't be uploaded, so a composition that previews one can't render on Lumiscia (see [What you can upload](../guides/media-sources#what-you-can-upload)).

Before you submit a composition that came from the browser, check it against your own rules (allowed node types, size, duration), since the render is billed to your workspace. The [Preview to render](../guides/preview-to-render) guide covers the full workflow.
